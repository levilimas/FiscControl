1. Visão Geral do Produto

1.1 Problema e Proposta de Valor

🎯 Problema Central

Pessoas físicas e autônomos não têm a mesma visão financeira-fiscal que a Receita Federal já possui sobre eles, o que gera:

  • Malha fina por inconsistências não detectadas
  • Multas inesperadas e evitáveis
  • Decisões financeiras ruins por falta de visibilidade
  • Medo e insegurança tributária

Contexto Legislativo Atual

O problema se agravou significativamente com três mudanças recentes:

  1. IN RFB nº 2.278/2025 - e-Financeira ampliada com mais instituições reportantes
  2. Rearp - Regularização e Atualização Patrimonial
  3. Integração fluxo financeiro + patrimônio - A Receita agora cruza dados de forma mais eficiente

💡 Proposta de Valor

"A Receita já sabe. Nosso app garante que você saiba antes."

Entregar ao contribuinte uma visão consolidada, inteligível e antecipada da sua realidade financeira e fiscal, usando IA para eliminar fricção na entrada de dados.

2.2 O Que Entra e Sai do MVP

✅ ENTRA no MVP (8 semanas)

Features Críticas

  • Autenticação completa (JWT + Refresh Token)
  • CRUD de transações (manual, voz, foto)
  • Múltiplas contas (cadastro e gestão)
  • Classificação fiscal assistida (IA + edição manual)
  • Visão consolidada (dashboard com totalizadores)
  • Upload de documentos (OCR para extração)
  • Entrada por voz (transcrição + NLP)
  • Cadastro de patrimônio (bens básicos)
  • Simulação IRPF básica (educativa)

❌ NÃO ENTRA no MVP (roadmap futuro)

Decisões Conscientes de Exclusão

1. Integração bancária via Open Finance

  • Complexidade: 3-4 semanas só nisso
  • Regulatório: precisa de certificação
  • Alternativa: entrada manual/foto/voz

2. Multi-usuário / Família

  • Compartilhamento de contas
  • Permissões granulares
  • MVP = 1 usuário por conta

3. Exportação completa de DIRPF

  • Gerar XML da Receita
  • Arriscado juridicamente
  • MVP = apenas simulação

4. Painel contador (B2B)

  • White label
  • Multi-cliente
  • Fase 3+

5. Importação bancária automática

  • Parsing de OFX/CSV complexos
  • MVP = upload manual simples

6. App web completo

  • MVP = mobile only
  • Web = apenas landing page

Fluxo de Processamento Assíncrono

1. User upload foto/áudio
        ↓
2. API recebe e valida
        ↓
3. Salva em Storage (S3)
        ↓
4. Enfileira Job (Redis/Bull)
        ↓
5. Worker processa em background
        ↓
6. Chama serviço externo (OCR/STT)
        ↓
7. Extrai dados estruturados
        ↓
8. Atualiza banco de dados
        ↓
9. Notifica usuário (status update)

4. Modelo de Dados

4.1 Entidades Principais

User (Usuário)

interface User {
  id: string;              // UUID
  email: string;           // UNIQUE
  password_hash: string;   // bcrypt
  name: string;
  cpf?: string;            // ENCRYPTED
  phone?: string;
  
  preferences: {
    default_context: 'PF' | 'AUTONOMO';
    notification_enabled: boolean;
    theme: 'light' | 'dark';
  };
  
  created_at: Date;
  updated_at: Date;
  last_login?: Date;
}

Account (Conta Bancária)

interface Account {
  id: string;
  user_id: string;         // FK -> User
  
  name: string;            // "Nubank", "BB Corrente"
  bank_name?: string;
  account_type: 'CORRENTE' | 'POUPANCA' | 'INVESTIMENTO' | 'OUTRO';
  
  initial_balance: number; // Saldo ao cadastrar
  current_balance: number; // Calculado
  
  is_active: boolean;
  created_at: Date;
  updated_at: Date;
}

Transaction (Transação)

enum TransactionType {
  CREDITO = 'CREDITO',
  DEBITO = 'DEBITO'
}

enum FiscalType {
  TRIBUTAVEL = 'TRIBUTAVEL',      // Salário, aluguel recebido
  ISENTO = 'ISENTO',               // Rendimento poupança
  DEDUTIVEL = 'DEDUTIVEL',         // Educação, saúde
  NEUTRO = 'NEUTRO',               // Transferências internas
  NAO_CLASSIFICADO = 'NAO_CLASSIFICADO'
}

enum InputSource {
  MANUAL = 'MANUAL',
  VOZ = 'VOZ',
  FOTO = 'FOTO',
  PDF = 'PDF',
  CSV = 'CSV',
  XML_NFE = 'XML_NFE'
}

interface Transaction {
  id: string;
  user_id: string;         // FK -> User
  account_id: string;      // FK -> Account
  
  date: Date;
  amount: number;          // Sempre positivo
  type: TransactionType;
  description: string;
  category?: string;
  
  fiscal_type: FiscalType;
  user_context: 'PF' | 'AUTONOMO';
  
  input_source: InputSource;
  original_input?: string;  // Texto original
  document_url?: string;    // URL do arquivo
  
  ai_confidence_score?: number;        // 0-1
  ai_suggested_fiscal_type?: FiscalType;
  user_confirmed: boolean;
  
  created_at: Date;
  updated_at: Date;
}

Asset (Patrimônio)

interface Asset {
  id: string;
  user_id: string;
  
  type: 'IMOVEL' | 'VEICULO' | 'INVESTIMENTO' | 'OUTRO';
  name: string;
  description?: string;
  
  acquisition_date: Date;
  acquisition_value: number;
  current_estimated_value: number;
  
  documents: string[];     // URLs
  
  created_at: Date;
  updated_at: Date;
}

4.2 Relacionamentos

User (1) ──────< (N) Account
User (1) ──────< (N) Transaction
User (1) ──────< (N) Asset
Account (1) ────< (N) Transaction

Cascade Delete:
• User deletado → deleta Accounts, Transactions, Assets
• Account deletado → deleta apenas suas Transactions

4.3 Índices Críticos

🚀 Performance desde o dia 1

users

  • UNIQUE INDEX: email
  • INDEX: cpf (encrypted)

accounts

  • INDEX: (user_id, is_active)
  • INDEX: (user_id, created_at DESC)

transactions (mais crítico)

  • INDEX: (user_id, date DESC)
  • INDEX: (account_id, date DESC)
  • INDEX: (user_id, fiscal_type)
  • COMPOSITE: (user_id, date, account_id) → para agregações

assets

  • INDEX: user_id
  • INDEX: (user_id, type)

Passo 8: Criar schema do Prisma

Editar prisma/schema.prisma:

generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

model User {
  id            String   @id @default(uuid())
  email         String   @unique
  passwordHash  String   @map("password_hash")
  name          String
  cpf           String?
  phone         String?
  preferences   Json     @default("{}")
  
  createdAt     DateTime @default(now()) @map("created_at")
  updatedAt     DateTime @updatedAt @map("updated_at")
  lastLogin     DateTime? @map("last_login")
  
  accounts      Account[]
  transactions  Transaction[]
  assets        Asset[]
  
  @@map("users")
}

model Account {
  id              String   @id @default(uuid())
  userId          String   @map("user_id")
  
  name            String
  bankName        String?  @map("bank_name")
  accountType     String   @map("account_type")
  
  initialBalance  Float    @map("initial_balance")
  currentBalance  Float    @map("current_balance")
  
  isActive        Boolean  @default(true) @map("is_active")
  
  createdAt       DateTime @default(now()) @map("created_at")
  updatedAt       DateTime @updatedAt @map("updated_at")
  
  user            User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  transactions    Transaction[]
  
  @@index([userId, isActive])
  @@map("accounts")
}

model Transaction {
  id                      String   @id @default(uuid())
  userId                  String   @map("user_id")
  accountId               String   @map("account_id")
  
  date                    DateTime
  amount                  Float
  type                    String
  description             String
  category                String?
  
  fiscalType              String   @map("fiscal_type")
  userContext             String   @map("user_context")
  
  inputSource             String   @map("input_source")
  originalInput           String?  @map("original_input")
  documentUrl             String?  @map("document_url")
  
  aiConfidenceScore       Float?   @map("ai_confidence_score")
  aiSuggestedFiscalType   String?  @map("ai_suggested_fiscal_type")
  userConfirmed           Boolean  @default(false) @map("user_confirmed")
  
  createdAt               DateTime @default(now()) @map("created_at")
  updatedAt               DateTime @updatedAt @map("updated_at")
  editedByUserAt          DateTime? @map("edited_by_user_at")
  
  user                    User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  account                 Account  @relation(fields: [accountId], references: [id], onDelete: Cascade)
  
  @@index([userId, date(sort: Desc)])
  @@index([accountId, date(sort: Desc)])
  @@index([userId, fiscalType])
  @@index([userId, date, accountId])
  @@map("transactions")
}

model Asset {
  id                      String   @id @default(uuid())
  userId                  String   @map("user_id")
  
  type                    String
  name                    String
  description             String?
  
  acquisitionDate         DateTime @map("acquisition_date")
  acquisitionValue        Float    @map("acquisition_value")
  currentEstimatedValue   Float    @map("current_estimated_value")
  
  documents               String[]
  
  createdAt               DateTime @default(now()) @map("created_at")
  updatedAt               DateTime @updatedAt @map("updated_at")
  
  user                    User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  
  @@index([userId])
  @@index([userId, type])
  @@map("assets")
}

10.1 Autenticação e Autorização

JWT Strategy

  • Access Token: 15 minutos de validade
  • Refresh Token: 7 dias de validade
  • Tokens armazenados no SecureStore no mobile
  • Renovação automática antes de expirar

@Controller('transactions')
@UseGuards(JwtAuthGuard)
export class TransactionsController {
  // Todas as rotas protegidas
}

Rate Limiting

  • 100 requisições por minuto por IP
  • 10 tentativas de login por hora
  • Rate limit específico para endpoints de IA (mais restritivo)

10.2 LGPD e Proteção de Dados

🔒 Dados Sensíveis

CPF

  • Armazenado criptografado (AES-256)
  • Nunca enviado em logs
  • Só descriptografado quando necessário

Senhas

  • Hash com bcrypt (salt rounds: 10)
  • Nunca armazenadas em texto plano
  • Nunca enviadas em logs ou respostas

Dados Financeiros

  • Conexão HTTPS obrigatória
  • Backup criptografado
  • Logs sanitizados (sem valores)

Consentimento do Usuário

No registro, o usuário deve aceitar:

  • Termos de Uso
  • Política de Privacidade
  • Consentimento LGPD para processamento de dados

Direitos do Usuário (LGPD)

  • ✅ Exportar todos os seus dados
  • ✅ Deletar conta e todos os dados
  • ✅ Corrigir informações
  • ✅ Revogar consentimento
